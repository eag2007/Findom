# ТЕХНИЧЕСКОЕ ЗАДАНИЕ: Поисковая система индексации веб-сайтов

---

## 1. ОПИСАНИЕ СИСТЕМЫ

Система индексирует веб-сайты из RSS-лент и предоставляет поиск с ранжированием по релевантности. Поддерживает русский и английский языки, морфологический анализ, поиск по точным фразам.

## 3. СХЕМА РАБОТЫ СИСТЕМЫ

### 3.1. Процесс индексации (добавление сайта в базу)

```text
┌─────────────────────────────────────────────────────────────────┐
│ 1. Парсинг RSS-ленты                                            │
│    - Получаем список статей из source_feed_uri                  │
│    - Для каждой статьи извлекаем: title, content, authors,      │
│      links, categories, publish_date                            │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ 2. Проверка дубликатов                                          │
│    - Считаем hash_title_content = hash(title + content)         │
│    - Проверяем: есть ли такая запись в Indexer-Data-Website     │
│    - Если есть → пропускаем или обновляем                       │
│    - Если нет → продолжаем                                      │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ 3. Сохранение основных данных                                   │
│    - INSERT в Indexer-Data-Website                              │
│      (title, content, hash_title_content, short_content,        │
│       publish_date, base_uri, source_feed_uri)                  │
│    - Получаем id_data_website (автоматически)                   │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ 4. Сохранение связанных данных                                  │
│    - INSERT в Indexer-Links (все ссылки из статьи)              │
│    - INSERT в Indexer-Authors (все авторы)                      │
│    - INSERT в Indexer-Contributors (все контрибьюторы)          │
│    - INSERT в Indexer-Categories (все категории)                │
│    - Все записи связываются через id_data_website               │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ 5. Построение поискового индекса                                │
│    - Определяем язык текста (русский или английский)            │
│    - Создаём tsvector из title (вес A - высокий приоритет)      │
│    - Создаём tsvector из content (вес B - средний приоритет)    │
│    - Объединяем: search_vector = title_vector + content_vector  │
│    - INSERT в Indexer-Search-Index                              │
│      (id_data_website, search_vector_ru, search_vector_en)      │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2. Процесс поиска (ответ на запрос пользователя)

```text
┌─────────────────────────────────────────────────────────────────┐
│ 1. Получение запроса                                            │
│    - Пользователь вводит: "как собрать компьютер"               │
│    - Определяем язык запроса (русский или английский)           │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ 2. Преобразование запроса в tsquery                             │
│    - Разбиваем на слова: [как, собрать, компьютер]              │
│    - Создаём tsquery: 'как & собрать & компьютер'               │
│    - Оператор & означает "все слова должны присутствовать"      │
│    - Если нужен поиск точной фразы: 'собрать <-> компьютер'     │
│    - Оператор <-> означает "слова идут подряд"                  │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ 3. Поиск по индексу                                             │
│    - SELECT из Indexer-Search-Index                             │
│    - WHERE search_vector_ru @@ tsquery                          │
│    - Оператор @@ проверяет совпадение                           │
│    - GIN-индекс обеспечивает мгновенный поиск                   │
│    - Получаем список id_data_website                            │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ 4. Ранжирование результатов                                     │
│    - Считаем ts_rank для каждого результата                     │
│    - ts_rank учитывает:                                         │
│      * Вес совпадений (A > B > C > D)                           │
│      * Частоту слов                                             │
│      * Длину документа                                          │
│    - Сортируем: ORDER BY rank DESC                              │
│    - Ограничиваем: LIMIT 10 (топ-10 результатов)                │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ 5. Получение данных для отображения                             │
│    - JOIN Indexer-Data-Website по id_data_website               │
│    - Получаем: title, short_content, publish_date, base_uri     │
│    - НЕ загружаем content на этом этапе                         │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ 6. Формирование сниппетов                                       │
│    - Для каждого результата загружаем content                   │
│    - Находим вхождение поисковых слов                           │
│    - Вырезаем фрагмент текста вокруг слова (150-200 символов)   │
│    - Подсвечиваем поисковые слова                               │
│    - Формируем short_description                                │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ 7. Возврат результатов                                          │
│    - Для каждой записи возвращаем:                              │
│      * title                                                    │
│      * short_description (сниппет с подсветкой)                 │
│      * publish_date                                             │
│      * full_url (base_uri + uri из Indexer-Links)               │
│      * authors (из Indexer-Authors)                             │
│      * categories (из Indexer-Categories)                       │
└─────────────────────────────────────────────────────────────────┘
```

## 4. ОПРЕДЕЛЕНИЯ ТЕРМИНОВ

### 4.1. TSVECTOR
Полнотекстовый индекс PostgreSQL. Представляет собой список нормализованных слов (лексем) с их позициями в документе.

**Пример:**
```
Текст: "Сборка компьютера для начинающих"
TSVECTOR: 'сборк':1 'компьютер':2 'начинающ':3
```

Слова приведены к начальной форме (морфология):
- "Сборка" → "сборк"
- "компьютера" → "компьютер"
- "начинающих" → "начинающ"

### 4.2. TSQUERY
Поисковый запрос в формате PostgreSQL.

**Операторы:**
- `&` — логическое И (все слова должны присутствовать)
- `|` — логическое ИЛИ (хотя бы одно слово)
- `<->` — слова идут подряд (точный поиск фразы)
- `<N>` — расстояние между словами (N слов между ними)

**Примеры:**
```
'собрать & компьютер'           — найти документы с обоими словами
'собрать | построить'           — найти документы с любым из слов
'собрать <-> компьютер'         — найти точную фразу "собрать компьютер"
'собрать <2> компьютер'         — "собрать" и "компьютер" через 2 слова
```

### 4.3. ВЕСА ПОИСКА (A, B, C, D)
PostgreSQL поддерживает 4 уровня важности для слов:
- **A** — самый важный (заголовки)
- **B** — важный (основной текст)
- **C** — обычный (дополнительная информация)
- **D** — наименее важный (служебный текст)

При ранжировании совпадения в заголовке (вес A) дают больше очков, чем совпадения в тексте (вес B).

### 4.4. GIN-ИНДЕКС
Generalized Inverted Index — тип индекса для полнотекстового поиска. Обеспечивает мгновенный поиск по tsvector без полного сканирования таблицы.

### 4.5. СНИППЕТ
Краткий фрагмент текста из статьи, показываемый в результатах поиска. Содержит поисковые слова с подсветкой.

**Пример:**
```
Запрос: "собрать компьютер"
Сниппет: "...Пошаговая инструкция как собрать компьютер в домашних условиях..."
```

### 4.6. МОРФОЛОГИЧЕСКИЙ АНАЛИЗ
Приведение слов к начальной форме:
- Глаголы → инфинитив ("собираю" → "собирать")
- Существительные → именительный падеж единственного числа ("компьютеры" → "компьютер")
- Прилагательные → именительный падеж ("красивые" → "красивый")

Обеспечивает поиск независимо от формы слова.

## 5. ТРЕБОВАНИЯ К РЕАЛИЗАЦИИ

### 5.1. Индексы базы данных
```text
Indexer-Data-Website:
  - PRIMARY KEY (id_data_website)
  - UNIQUE (hash_title_content)
  - INDEX (publish_date)
  - INDEX (source_feed_uri)

Indexer-Links:
  - PRIMARY KEY (id)
  - FOREIGN KEY (id_data_website)
  - INDEX (id_data_website)
  - INDEX (uri)

Indexer-Authors:
  - PRIMARY KEY (id)
  - FOREIGN KEY (id_data_website)
  - INDEX (id_data_website)

Indexer-Contributors:
  - PRIMARY KEY (id)
  - FOREIGN KEY (id_data_website)
  - INDEX (id_data_website)

Indexer-Categories:
  - PRIMARY KEY (id)
  - FOREIGN KEY (id_data_website)
  - INDEX (id_data_website)

Indexer-Search-Index:
  - PRIMARY KEY (id_data_website)
  - FOREIGN KEY (id_data_website)
  - GIN INDEX (search_vector_ru)
  - GIN INDEX (search_vector_en)
```

### 5.2. Ограничения
- Максимальный размер title: не ограничен (TEXT)
- Максимальный размер content: не ограничен (TEXT)
- Максимальный размер URI: 2000 символов
- Поддерживаемые языки: русский, английский
- Минимальная длина поискового запроса: 1 слово
- Максимальная длина поискового запроса: не ограничена

### 5.3. Производительность
- Время индексации одной статьи: < 100 мс
- Время поиска: < 500 мс для 100 000 статей
- Количество результатов на странице: 10 (настраивается)
- Поддержка пагинации: обязательна

## 6. ПРИМЕРЫ ИСПОЛЬЗОВАНИЯ

### 6.1. Простой поиск
```text
Запрос: "собрать компьютер"
Результат: Статьи, содержащие оба слова в любой форме
```

### 6.2. Поиск точной фразы
```text
Запрос: "собрать компьютер" (в кавычках)
Результат: Статьи, где слова идут подряд
```

### 6.3. Поиск с фильтрацией по дате
```text
Запрос: "собрать компьютер"
Фильтр: publish_date >= '2024-01-01'
Результат: Только статьи после 1 января 2024
```

### 6.4. Поиск по категории
```text
Запрос: "собрать компьютер"
Фильтр: category = "Технологии"
Результат: Только статьи из категории "Технологии"
```

## 7. КОНФИГУРАЦИЯ

### 7.1. Параметры поиска
```text
results_per_page: 10          — количество результатов на странице
snippet_length: 200           — длина сниппета в символах
highlight_tag: '<mark>'       — тег для подсветки слов
min_word_length: 3            — минимальная длина слова для поиска
```

### 7.2. Параметры индексации
```text
title_weight: 'A'             — вес заголовка
content_weight: 'B'           — вес основного текста
language_detection: true      — автоматическое определение языка
morphology: true              — использовать морфологический анализ
```
